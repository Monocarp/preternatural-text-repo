o	Function/component signatures with docstrings
o	Module dependency graph (what imports what)
o	Feature domains (auth, search, tag tree, story rendering)

2. Task-Scoped Context Retrieval When you say "Add scoped search inside tag branch":
•	LLM generates embedding for the request
•	Vector search returns: 
o	Relevant modules (e.g., TagTree.tsx, SearchBar.tsx, db/queries.ts)
o	Dependency chain (DB schema → API routes → UI components)
o	Similar existing features (existing search implementations)
•	Total context: ~500-2K tokens instead of 50K+
3. Execution Pipeline
Planning Phase (Claude Sonnet 4.5)
├─ Analyze retrieved modules only
├─ Generate implementation plan with affected files
└─ Estimate complexity & conflicts

Implementation Phase (Artifacts/Code Execution)
├─ Generate changes file-by-file
├─ Run incremental type checks (tsc --noEmit per module)
└─ Generate tests for new functions

Review Phase (automated + human)
├─ Diff preview with architectural impact notes
├─ Run test suite
└─ You approve/reject before applying

// pseudo-code
async function executeFeature(request) {
  // 1. Retrieve context (200-500 tokens)
  const context = await vectorDB.search(request);
  
  // 2. Plan (1 LLM call, ~1K tokens)
  const plan = await claude.plan(request, context);
  
  // 3. Execute per file (N calls of ~500 tokens each)
  for (const file of plan.files) {
    const changes = await claude.implement(file, plan);
    await fs.writeFile(file.path, changes);
    await runTests(file);
  }
  
  // 4. Summary review (1 call, ~800 tokens)
  return await claude.review(plan, testResults);
}
Key Cost-Saving Patterns
1.	Hierarchical planning: Generate high-level plan first (cheap), then implement file-by-file (focused context)
2.	Caching: Use Claude's prompt caching for your dependency graph and type definitions
3.	Incremental indexing: Only re-embed files you've changed
4.	Smart boundaries: Tag system changes shouldn't pull in auth code—enforce module isolation in your index
What This Gets You
•	Architectural coherence: RAG retrieves your existing patterns (e.g., "all API routes follow this error handling pattern")
•	No hallucinations: LLM only sees real code from your index, not inventing APIs
•	Cheap iteration: $0.50-2 per feature instead of $10+ dumping full context
•	Audit trail: Every change is planned → implemented → tested → reviewed as discrete steps
