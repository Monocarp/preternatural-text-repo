### Overview of Your AI-Assisted Development Infrastructure

Your "Preternatural Text" repo sounds like a fascinating project—a Node.js/React frontend with a backend DB for tagged supernatural stories. As a solo dev, scaling AI assistance without token bloat, hallucinations, or manual file-wrangling is crucial. The goal is a **modular, agentic workflow** that treats your codebase like a living system: index it once (or periodically), retrieve surgically for each task, plan holistically, edit incrementally, and review via diffs/tests—all while keeping you in the loop for approvals.

This setup avoids full-repo prompts by using **Retrieval-Augmented Generation (RAG)** for context, **file-scoped editing** for changes, and **git-based versioning** for safety. It's low-cost (~$5-20/month in API fees for moderate use, or free with local LLMs), reliable (open-source core), and scales as your repo grows (re-index every 1-2 weeks or on major commits). Total setup time: 2-4 hours initially, then ~5-10 min per feature.

### Core Architecture
The system breaks into four phases, orchestrated via a simple Python script (using LangChain for chaining, but kept lightweight—no heavy deps). You input "Add scoped search inside a tag branch" via CLI/chat, and it outputs a git branch with changes ready for your review.

1. **Indexing & Retrieval (RAG Layer)**: Embed your codebase into a vector store. For a feature request, query it to fetch *only* relevant files/modules (e.g., search logic, tag DB schema, React components for branches). This keeps prompts under 4K-8K tokens/task.
   
2. **Planning Agent**: LLM analyzes retrieved context + your request to output a task breakdown (e.g., "1. Update DB query in models/tag.js; 2. Add React hook in components/Search.tsx"). Identifies risks like module conflicts.

3. **Execution Agent**: Edits files incrementally (one or few at a time), generating diffs. No full-repo awareness needed here—relies on planning + local file context.

4. **Review & Integration**: Auto-run tests/lints, show git diffs. You approve/merge. If issues, rollback via git.

**Orchestration Script**: A ~100-line Python CLI (I'll sketch it below). Run locally with `python dev-agent.py "Add feature X"`. Uses Ollama (local LLM) for planning/review to minimize costs, or OpenAI for execution if needed.

**Scalability Notes**:
- Repo growth: Re-index adds ~1-2 min; vector store handles 100K+ lines easily.
- Coherence: Planning enforces architecture (e.g., "Keep React stateless, DB queries via ORM").
- Cost Control: Local models for 80% of work; cap API calls at 10K tokens/task.

### Implementation Steps
1. **Setup RAG (10-15 min)**:
   - Install: `pip install codrag` (or clone repo).
   - Index: `python index_codebase.py --repo /path/to/preternatural-text --languages js,ts,sql`.
   - Query test: `python query.py "Files for tag-based story search"` → Outputs snippets like `models/stories.js: queryBuilder.addWhere('tags', 'contains', branchId)`.

2. **Install Core Tools (10 min)**:
   - Aider: `pip install aider-chat`.
   - Continue.dev: VS Code extension → Configure with Ollama endpoint.
   - Test: In repo dir, `aider --model ollama/codellama` → "Map my repo" to build its internal graph.

3. **Build Orchestrator Script (30-60 min)**:
   Use this as a starter (save as `dev-agent.py`; requires `pip install langchain langchain-community faiss-cpu`):

   ```python
   from langchain_community.llms import Ollama
   from langchain.prompts import PromptTemplate
   from codrag import CodeRAG  # Assuming CodeRAG API
   import subprocess
   import sys

   # Init
   rag = CodeRAG.from_index('preternatural_index')  # Your indexed store
   llm = Ollama(model="codellama")

   # Phase 1: Retrieve
   def retrieve_context(query):
       return rag.query(query, top_k=5)  # e.g., {'files': ['tag.js', 'Search.tsx'], 'snippets': [...]}

   # Phase 2: Plan
   plan_prompt = PromptTemplate(
       input_variables=["query", "context"],
       template="""Based on this codebase context: {context}
       Plan adding feature: {query}. Output JSON: {{"tasks": ["task1: fileX"], "risks": ["potential conflict"]}}"""
   )
   def plan_feature(user_query):
       context = retrieve_context(user_query)
       return llm(plan_prompt.format(query=user_query, context=context))

   # Phase 3: Execute with Aider
   def execute_tasks(plan_json):
       tasks = plan_json['tasks']
       for task in tasks:
           subprocess.run(['aider', '--message', task, '--auto-commits'])

   # Phase 4: Review
   def review_changes():
       subprocess.run(['git', 'diff', 'HEAD~1'])  # Show diff
       print("Approve? (y/n)")  # Human loop
       if input().lower() == 'y':
           subprocess.run(['git', 'commit', '-m', 'AI: Feature X'])
       else:
           subprocess.run(['git', 'reset', 'HEAD~1'])

   # CLI Run
   if __name__ == "__main__":
       query = sys.argv[1]
       plan = plan_feature(query)
       execute_tasks(plan)
       review_changes()
   ```

   - Run: `python dev-agent.py "Add scoped search inside a tag branch"`.
   - Customize: Add your DB schema to prompts for coherence (e.g., "Enforce Prisma ORM patterns").

4. **Test & Iterate (Ongoing)**:
   - Start small: Add a dummy feature, measure tokens (via OpenAI dashboard if using API).
   - Metrics: Track time-to-feature (aim <1hr), hallucination rate (0 via reviews), cost (<$0.10/task).
   - Re-index: Hook into git post-commit: `git hook → python reindex.py`.
   - For DB changes: Add a step to generate/run migrations (e.g., via Prisma integrate).

### Potential Challenges & Mitigations
- **Hallucinations/Conflicts**: Planning uses RAG for grounded context; Aider's file-map spots cross-module issues. Always review diffs—your human veto.
- **Token Burn**: RAG caps at ~2K input/task; local Ollama for planning. If scaling, switch to Grok API (x.ai/api) for efficiency.
- **Reliability**: Open-source means community fixes (Aider has 10K+ GitHub stars). Backup repo daily.
- **Your Loop**: Every commit needs your `y/n`; add voice commands via Aider's /voice for hands-free.
